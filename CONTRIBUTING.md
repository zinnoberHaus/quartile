# Contributing

Quartile welcomes issues, documentation, research, and code. While the library's language and scope are undecided, the most useful contributions are proposals that describe a concrete problem the library should solve.

For a bug, include a reproducible example, expected and actual results, and relevant versions. Remove secrets and personal data. For a substantial change, first open an issue explaining the user problem, proposed behavior, alternatives, and acceptance criteria. Report vulnerabilities through [SECURITY.md](SECURITY.md).

Work in a branch and submit a focused pull request. Explain what changed, why, and the checks performed. Update affected documentation. Run the repository's documented checks. Cite primary sources for research and distinguish evidence from proposals. Keep generated artifacts and lockfiles consistent with their sources.

Contributions use the repository's license. You must have the right to submit the material and preserve third-party notices. Sign off each commit using `git commit -s` to certify the [Developer Certificate of Origin](https://developercertificate.org/). A signoff is not a copyright transfer. Do not add a signoff for another person.

AI-assisted contributions are welcome. The submitting contributor remains responsible for correctness, provenance, security, and validation. Describe meaningful agent involvement and verification in the pull request. Do not upload secrets, confidential customer data, or material you lack permission to disclose.

The maintainer reviews scope, correctness, compatibility, documentation, security implications, and validation. Changes to architecture or project boundaries should include a written decision. Small documentation fixes need no new tests. Follow [GOVERNANCE.md](GOVERNANCE.md) and [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
