# Governance

Zinnober Haus is a founder-led open-source portfolio. The owner of the `zinnoberHaus` GitHub account is the initial accountable maintainer. There is no foundation, board, or promised commercial support service.

The umbrella repository owns shared context, agent roles, reusable workflows, portfolio research, and repository registry. Each product repository owns its implementation and product-specific decisions. Shared guidance must not silently overwrite product decisions or bypass repository permissions.

Anyone may propose changes through issues and pull requests. Maintainers seek practical consensus and record significant decisions, alternatives, and consequences in the repository. The account owner resolves unresolved scope, licensing, security, and release decisions. Decisions can be revisited with new evidence. A proposal or roadmap entry is not a delivery commitment.

Agents may research, prepare changes, and run authorized checks. They do not constitute independent human reviewers, own credentials, or acquire authority to delete repositories, publish releases, or change access through a role description. The human maintainer remains accountable for those actions and for reviewing generated work.

The owner may appoint maintainers after sustained reviewed contributions, documenting their GitHub identity, scope, and permissions in a pull request. Grant the minimum access needed. Maintainers may step down; removal or scope changes must be documented without publishing private incident details. Until another maintainer is appointed, independent review and conflict-of-interest escalation are limited.

Disagreements about technical decisions should stay focused on evidence and user outcomes. Conduct concerns follow the code of conduct; vulnerabilities follow the security policy. Changes to this governance document use a public pull request and an explanation of their effects.
