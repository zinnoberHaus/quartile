Charts from code blocks

Fictional sample data. This file has no build step: it includes one script and writes ```quartile blocks as ordinary <pre><code> markup, which is what Markdown renderers such as MkDocs, Hugo, Jekyll and dbt docs produce. Switch to dark mode: the charts follow the page.

Revenue by region

The rows come from sales.csv next to this page, loaded once and shared. The chart states its source, and its buttons open the rows behind it or save them as CSV. 

data sales
src: sales.csv
revenue.format: currency USD

barlist sum(revenue) by region
title: Revenue by region, Q3 2026
source: sales.csv, fictional sample data
asof: 2026-09-30
actions: rows, download
data: sales

Every chart over sales follows a selection

Click a region above. No setting asks for this: blocks that read one named dataset select and filter each other, and the rows behind the first chart narrow with them. 

line sum(revenue) by month and channel
title: Revenue by channel
data: sales

dashboard
data: sales
kpi sum(revenue) as "Revenue"

What the page hears

A chart dispatches a quartile-select event when its selection changes. The page's own script, shown at the end of this page, prints the latest one here.

An API response

tickets.json next to this page is shaped like an API response: a status, the rows under data.results and a request id. path says where the rows are. 

bar sum(tickets) by week and priority
title: Support tickets opened per week
stacked: yes
src: tickets.json
path: data.results

How this page is wired

One script tag, which also says what blocks may load:

<script src="quartile.global.js"
  data-theme="auto"
  data-sources="same-origin"></script>

data-sources="same-origin" lets blocks load files from this site. Without it, no block fetches anything.
