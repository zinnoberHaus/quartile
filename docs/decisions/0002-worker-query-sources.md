# 0002: Optional worker query sources

Date: 2026-10-09 · Status: accepted for implementation · Issue: [#8](https://github.com/zinnoberHaus/quartile/issues/8)

## Context

The original design includes Arrow and DuckDB input. Existing Quartile components consume synchronous JavaScript rows and apply linked filters before local aggregation. Converting an entire Arrow table to objects before rendering would preserve that path's cost and would not deliver the design's worker query capability. Decision 0001 excluded these inputs from the initial preview; this decision authorizes an optional preview extension, not a stable release or a performance guarantee.

## Evidence

- Arrow tables expose schema, batches and vectors. Numeric vector extraction is zero-copy only under specific type/chunk conditions; row proxies and nullable buffers require deliberate conversion. [Arrow Table](https://arrow.apache.org/js/current/classes/Arrow.dom.Table.html), [Vector](https://arrow.apache.org/js/current/classes/Arrow.dom.Vector.html).
- DuckDB-Wasm runs through an asynchronous worker API, supports Arrow ingestion and prepared parameter values, and returns Arrow query results. Worker and Wasm assets must match. [Instantiation](https://duckdb.org/docs/current/clients/wasm/instantiation), [ingestion](https://duckdb.org/docs/current/clients/wasm/data_ingestion), [queries](https://duckdb.org/docs/current/clients/wasm/query).
- `cancelSent()` is documented for pending sent queries. Prepared queries follow a different implementation path; stale-result suppression and a serialized queue remain necessary even when interruption is unavailable. [Connection API](https://shell.duckdb.org/docs/classes/index.AsyncDuckDBConnection.html).
- Mosaic separates a client's data requirements and result lifecycle from a coordinator and connector. Its selection strategies are richer than Quartile's one-predicate-per-field contract; replacing Quartile's store would change semantics. [Client](https://idl.uw.edu/mosaic/api/core/client.html), [coordinator](https://idl.uw.edu/mosaic/api/core/coordinator.html), [selection](https://idl.uw.edu/mosaic/api/core/selection.html).

## Decision

1. Keep `DataInput`, `dataset()` and `resolveData()` synchronous and backward compatible. Add an explicit query contract and React integration separately. A query source performs source-excluding predicates before aggregation and returns bounded rows with result metadata. Existing charts may consume these prepared results through the query integration without filtering or aggregating them twice.
2. Publish optional `@quartile/react/query` and `@quartile/react/duckdb` entry points. The default React entry must not import Arrow, DuckDB, or start a worker. The adapter uses `@duckdb/duckdb-wasm` **1.32.0** and `apache-arrow` **17.0.0** for initial verification. On 2026-10-09 the npm `latest` tag points to a prerelease; 1.32.0 is the newest published non-prerelease. Its dependency specifies Arrow `^17.0.0`; newer Arrow majors are not implicitly supported.
3. The application supplies an existing database, an exclusively borrowed connection, or an explicit owned factory with cleanup. No worker starts at module import. Adapter-created connections and private imported relations are owned by the adapter. Borrowed databases/connections remain caller-owned. Disposal is asynchronous and idempotent.
4. Accept Arrow 17 tables or IPC bytes and copy them into immutable private relations. Derive field types from physical Arrow metadata, then apply display overrides. Support signed/unsigned integers up to 32 bits, Float32/Float64, booleans, Utf8/dictionary-Utf8, DateDay/DateMillisecond, and timestamps in seconds or milliseconds. Reject Int64/Uint64, Float16, decimals, nested/binary values, and sub-millisecond timestamps rather than silently losing precision. Preserve original physical type, nullability, timestamp unit and timezone as source column metadata. Do not materialize all raw rows into React.
5. Compile typed row, aggregate and histogram plans into SQL. Table names are private generated identifiers; field names and output aliases are checked against metadata and quoted. All predicate values are bound parameters. Dashboard JSON cannot select raw SQL, file URLs, or extensions.
6. Serialize operations per backend connection. Abort removes pending work and suppresses results from active canceled work; graceful connection cleanup waits for active prepared execution to settle. Backend disposal with an explicitly owned factory instead invokes its database/worker termination directly, which releases all its resources even if a worker request never settles. Do not call connection-scoped interruption in a way that could cancel another view's query. Engine interruption is a separately verified capability, not a universal promise of `AbortSignal`.
7. Normalize boundary semantics explicitly: null and empty aggregate inputs, boolean exclusion from numeric aggregation, count(field) versus count rows, inclusive predicate ranges, histogram boundary inclusion, date units, deterministic ordering, and result limits. Unsupported ambiguous coercions produce errors. Function formatters stay on the main thread.
8. Keep SVG rendering and query execution independent. Benchmark query, bounded-result conversion and browser rendering separately. No universal row-count threshold, zero-copy guarantee, multithreading guarantee, or million-row interaction claim follows from adding this adapter.

## Query semantics and limits

- A field's physical Arrow type controls predicates. Strings remain literal, including ISO-looking strings. Numeric and boolean predicates do not coerce strings or dates. Temporal predicates accept dates, epoch milliseconds and ISO date strings parsed with JavaScript's `Date.parse`; date-only strings denote UTC midnight, unlike the legacy row path's local date parser. Temporal results are JavaScript dates. Display overrides cannot change physical field types. Timestamp timezone metadata describes the input; comparison uses epoch milliseconds.
- Predicates combine with AND. Equality and inclusion support null explicitly. Ranges are inclusive, accept null for an open bound, and require numeric or temporal fields. Unsupported fields, operators, sort directions and type mismatches fail before SQL execution. Predicate values use prepared bindings; quoted allowlisted identifiers are the only names compiled into SQL.
- Numeric aggregates require physical numeric fields and ignore nonfinite values and nulls. An empty sum is zero; empty mean/min/max are null. Nonfinite aggregate output (for example, an overflowing sum of finite inputs) rejects the query; raw row queries preserve the physical float values. `count` without a field counts rows. `count(field)` excludes null and, for string fields, empty strings; it counts nonfinite numeric inputs. Booleans are not numeric measures. These are typed-source rules; the legacy synchronous row path's permissive coercions are unchanged.
- Histogram edges are finite and strictly increasing. Bins include their lower edge and exclude their upper edge, except the final bin includes both. Empty bins remain present. Output fields are `x0`, `x1`, and `count`; values outside the supplied edges and nonfinite values are excluded.
- Ordering uses DuckDB's binary string order and explicit nulls last. Row queries append a private ingestion ordinal to break ties, while aggregate queries append grouping fields. This differs from the synchronous table's locale-aware string sorting; worker pages retain query ordering. Arrow names must be unique ignoring case because DuckDB identifiers are case insensitive. The private name `__q_row_ordinal` is reserved.
- Each row/group query returns at most 10,000 rows; each histogram accepts at most 1,000 bins. A query accepts at most 100 predicates and 100 measures, and an inclusion predicate at most 1,000 values. Window offsets must be nonnegative safe integers. `totalRows` is the exact filtered row/group count before paging/limits, and `complete` means the returned result contains the entire requested result set. Histogram totals describe bins. Unsafe integer results fail rather than losing precision.
- The adapter serializes one exclusively used connection, including ingestion and source disposal. Abort immediately rejects the caller, skips queued execution, and suppresses active results. It does **not** promise to interrupt an executing prepared statement. Source disposal aborts that source, waits behind active work and drops its relation. Backend disposal with a borrowed database or connection waits for active work, drops relations and closes an adapter-created connection; borrowed resources remain usable. With an owned factory, backend disposal aborts query/import callers and directly runs the factory's required database/worker termination without awaiting pending SQL. That termination releases all owned relations and connections; it also handles fatal worker errors that leave upstream query promises unresolved.

Arrow ingestion serializes a complete IPC copy before worker import and creates a private table with its ordering ordinal. This incurs main-thread serialization and transient memory duplication; it is neither streaming ingestion nor a zero-copy path. Only bounded query results are converted to plain row objects. Source revisions are immutable; changes require a new source. This adapter does not read remote files, execute caller SQL, load extensions, or choose a worker bundle.

## Consequences

Applications must serve compatible worker/Wasm assets; Vite's documented `?url` pattern is supported by the example. Single-thread worker execution is the baseline and does not require COOP/COEP. Caller authorization remains upstream of browser data ingestion. Browser testing must cover real ingestion, linked selection, failures, cancellation races, disposal, and asset loading before this integration is described as working.

The npm release remains blocked on the separate naming/scope/release decisions. This extension remains an experimental API within the source preview.
