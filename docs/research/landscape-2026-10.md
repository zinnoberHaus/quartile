# Landscape: open-source data visualization for React (October 2026)

This note compares Quartile's planned design with the open-source libraries and frameworks it will be measured against. All facts were checked on 2026-10-07. Versions and publish dates come from the npm registry (or PyPI for Streamlit). Star counts come from the GitHub API and are rounded to show order of magnitude only. Behaviour claims link to each project's own docs, source or release notes. Sentences marked **Opinion** are our judgement, not sourced facts. Quartile has not shipped any code yet. Everything this note says about Quartile describes what the design intends to build, not what exists today.

## Where the gaps are

These gaps cover only the libraries reviewed above. We did not survey every library.

1. **Chart libraries stop at the chart.** Recharts, ECharts, Plot, Unovis, visx, Nivo, Chart.js and Plotly ship charts and in-chart controls such as brushes, zoom and legends. None of them ships general application controls like buttons, date pickers, filter bars or data tables (see each library's README above). **Opinion:** in practice this means a team themes a chart library and a UI kit separately and passes data between them by hand.

2. **UI kits stop at the form, and their charts are wrappers.** shadcn/ui's chart is Recharts plus a container, tooltip and legend, and the docs say it intentionally does not wrap Recharts ([docs](https://ui.shadcn.com/docs/components/radix/chart)). Its data table is a guide to building your own table on TanStack Table, not a component ([docs](https://ui.shadcn.com/docs/components/radix/data-table)). No state links a chart to the table or the inputs on the same page. Tremor follows the same Recharts-based approach and has had no release since January 2025.

3. **Linked selection exists, but not as a primitive in open-source React component kits.** Among the libraries reviewed:
   - Crossfilter semantics are first-class in Mosaic, which is framework-agnostic and DuckDB-backed, with React integration through `makeClient` ([docs](https://idl.uw.edu/mosaic/web-clients/)).
   - In Vega-Lite they apply to views composed within one spec ([example](https://vega.github.io/vega-lite/examples/interactive_crossfilter.html)).
   - Other libraries offer weaker linking. Recharts' `syncId` syncs tooltips and brushes, not data. ECharts' `connect` syncs interaction across instances.
   - Where grid-and-chart linking does ship in React, it is paid: MUI X Premium's Charts and Data Grid integration, and AG Grid Enterprise's cross-filter charts, which AG Grid says are no longer actively developed.

   We found no MIT- or Apache-licensed React component library in which charts, tables and inputs share one selection store with crossfilter semantics.

4. **Chart accessibility is real but uneven, and mostly partial.** Recharts 3 ([release](https://github.com/recharts/recharts/releases/tag/v3.0.0)) and MUI X Charts ([docs](https://mui.com/x/react-charts/accessibility/)) enable keyboard navigation by default; MUI marks its version as under development. AG Charts adds screen-reader announcements in its free tier ([docs](https://www.ag-grid.com/charts/react/accessibility/)). ECharts generates descriptions only when `aria.show` is set ([docs](https://echarts.apache.org/handbook/en/best-practices/aria/)). shadcn/ui's chart docs still describe `accessibilityLayer` as something you turn on. We did not find a reviewed library that by default gives every chart a keyboard model, a text summary and an equivalent data table together. That combination is Quartile's target.

5. **Machine-readable specs exist for charts or for generic UI, but not for both together.** Vega-Lite and Mosaic publish JSON Schemas for chart and dashboard specs. json-render and A2UI validate LLM output against UI component catalogs; json-render's prebuilt catalog is shadcn/ui components, not linked charts. shadcn/ui publishes a JSON schema for registry items, which describes files and dependencies for distribution, not component props ([registry-item.json](https://ui.shadcn.com/schema/registry-item.json)). The gap Quartile targets is one schema set that covers charts, tables, controls and the selections that connect them, so a generated dashboard can be validated as a whole.

## How Quartile differs from shadcn/ui

shadcn/ui is the most likely starting point for a React team that wants dashboards, so this comparison matters most. The Quartile column describes the design's intent.

| Dimension | shadcn/ui (verified) | Quartile (intended) |
|---|---|---|
| Distribution | The CLI copies component source into your project (`components/ui/`): "You own the code" ([docs](https://ui.shadcn.com/docs)). Fixes reach you through the headless dependencies (Radix, Base UI or React Aria); the styled layer is yours to maintain. | Versioned npm package (`@quartile/react`). Fixes and accessibility improvements arrive with an upgrade. Customisation goes through tokens, props and composition rather than edited source. |
| Styling | Tailwind CSS. `components.json` configures Tailwind, and theming uses CSS variables consumed through Tailwind ([docs](https://ui.shadcn.com/docs/components-json)). | Plain CSS custom properties with no Tailwind dependency. It should still sit inside a Tailwind app. |
| Charts | Recharts v3 composed directly, plus `ChartContainer`, tooltip, legend and five chart colour tokens ([docs](https://ui.shadcn.com/docs/components/radix/chart)). | Charts are first-class components that share the data model, formats, tokens and selection store with every other component. |
| Data table | A guide for building your own on TanStack Table ([docs](https://ui.shadcn.com/docs/components/radix/data-table)). | A packaged data table that reads the same column types and formats and takes part in selections. |
| Data model | None. Each chart receives an array and `dataKey` strings. | Typed columns with schema inference. Formats are attached once and reused by axes, tooltips, tables and KPIs. |
| Cross-view state | None shared between components. | `<Selection>` and `useSelection`, with crossfilter semantics: a view is never filtered by its own selection. |
| Chart accessibility | Inherits Recharts' `accessibilityLayer`. | Keyboard navigation, a screen-reader summary and a table fallback on every chart. |
| Machine-readable surface | Open code for LLMs to read, a registry schema, and an MCP server for finding and installing components ([MCP](https://ui.shadcn.com/docs/mcp)). | JSON Schema for each component's props, so a generated dashboard spec can be validated before it renders. |
| Density | **Opinion:** defaults are tuned for general application and marketing UI. | **Opinion:** defaults tuned for dense analytic layouts. This is a design goal, not a measured difference. |

**What shadcn/ui does better, and will keep doing better:**

- **Ownership.** Copied source can be edited without waiting for upstream or working around a package's API.
- **Breadth.** Its component docs cover roughly sixty components ([docs](https://ui.shadcn.com/docs)).
- **Choice of primitives.** You can build on Radix, Base UI or React Aria.
- **Ecosystem.** It has a registry ecosystem, an MCP server, and very large adoption (~125k GitHub stars).

**Opinion:** Quartile should position itself as something that works alongside shadcn/ui, not as a replacement. A team should be able to keep shadcn/ui for forms and navigation and use Quartile for the analytic surface, with a documented mapping between shadcn's CSS variables and Quartile's tokens.

## Risks and honest caveats

- **Recharts is the incumbent.** In the week 2026-09-30 to 2026-10-06, npm recorded about 59.5M downloads of `recharts`, 12.7M of `chart.js` and 5.5M of `echarts` ([npm downloads API](https://api.npmjs.org/downloads/point/2026-09-30:2026-10-06/recharts)). Download counts include CI and transitive installs, so they overstate direct use, but the size gap is real. Quartile has to justify adding a dependency, not just exist.
- **Catalog breadth.** ECharts, Plotly and Nivo offer far more chart types than a new library will have for a long time. Quartile should cover the chart types dashboards actually use and say clearly what it lacks.
- **Scale.** Mosaic already delivers interactive crossfiltering over very large tables by pushing queries to DuckDB and pre-aggregating ([paper](https://idl.uw.edu/papers/mosaic)). An in-memory selection store in the browser will hit limits much sooner. Quartile must publish its tested row counts, and **Opinion:** it should consider a pluggable query backend rather than claim scale it has not measured.
- **Accessibility depth.** AG Charts documents screen-reader testing on NVDA, JAWS, Narrator and VoiceOver ([docs](https://www.ag-grid.com/charts/react/accessibility/)). "Every chart is accessible" is only a credible claim if Quartile does the same testing and runs automated checks in CI.
- **Package vs copy-paste.** shadcn/ui's popularity shows many teams prefer owning the source. A package must offer enough escape hatches (slots, render props, token overrides) that teams do not feel locked in, and it must treat breaking changes carefully.
- **Commercial incumbents ship integration today.** MUI X Premium and AG Grid Enterprise already link grids and charts, with paid support. Quartile's open-source license is an advantage only if its integration is at least as dependable.
- **Generative UI is moving fast.** json-render and A2UI are both active and widely used. If Quartile's JSON Schemas cannot be used as a catalog by those tools, its LLM story will look isolated.
- **Sustainability.** Tremor shows that even a popular dashboard kit can stop releasing after a change of ownership. Quartile is new and maintained by a small organisation. Its governance and release cadence need to be visible from the start.
- **Nothing is shipped yet.** Every Quartile row above is a design commitment. None of it should be marketed until it is implemented and tested.
